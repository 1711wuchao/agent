# 合同类型与模板清单

| 合同类型编码 | 合同类型 | 模板文件/生成方式 | 核心字段 | 优先级 |
| --- | --- | --- | --- | --- |
| ZHONGCHENG_PURCHASE | 中城购销固定格式 | Java 专用生成逻辑 | 甲方、乙方、开票日期、品名、规格型号、单位、数量、税率、价税合计 | P0 |
| PURCHASE | 产品购销合同 | Java 生成逻辑 | 甲方、乙方、品名、规格型号、数量、税率、价税合计、开票日期 | P0 |
| TECH_DEVELOPMENT | 技术开发合同 | Java 生成逻辑 | 甲方、乙方、品名、规格型号、数量、税率、价税合计、开票日期、技术目标 | P0 |
| SERVICE | 服务合同 | `service-contract.docx` | 服务方、委托方、服务内容、服务周期、费用、成果交付 | P1 |
| NDA | 保密协议 | `nda.docx` | 披露方、接收方、保密范围、保密期限、违约责任 | P1 |
| SUPPLEMENT | 补充协议 | `supplement.docx` | 原合同编号、变更事项、生效日期、双方主体 | P1 |

## 中城固定模板规则

当甲方、乙方、购买方、销售方任一字段包含“中城”时，系统仍需先根据发票品名判断合同类型；品名包含“站点”“软件”“算法”的，生成技术开发合同，不使用中城固定购销格式。

仅当涉及“中城”且发票品名不属于技术开发范畴时，系统使用 `ZHONGCHENG_PURCHASE` 固定购销格式。

中城合同固定要求：

- 标题使用 `购 销 合 同`。
- 甲方显示为 `甲  方（需方）`，乙方显示为 `乙  方（供方）`。
- 签订地点固定为 `苏州市吴江区`。
- 合同签订日期按开票日期上月下旬生成，当前规则固定取上月 `26` 日。
- 第一章/前置规则：
  - 收入库单/提货。
  - 明确交货时间和地点。
  - 合同签订时间在开票时间上月下旬。
  - 合同中约定运费由我方公司承担。
  - 合同中不体现“通用设备”和“软件”字样。
- 商品表格固定为 6 列：`产品名称`、`规格/型号`、`单位`、`数量`、`总价(元)`、`备注`。
- 商品名称生成时自动移除 `通用设备`，并将 `软件` 替换为 `系统`。
- 运输及搬运费用由包含“中城”的合同方承担；销项合同中通常为乙方承担。
- 付款期限使用中城固定格式：货物交付完成、验收无误且货权交割后 60 个工作日内全款支付。
- 争议解决使用乙方所在地人民法院。

## 模板变量规范

- 变量格式统一使用 `{{变量名}}`。
- 变量必须在系统中登记，包括字段编码、字段名称、类型、是否必填、默认值。
- 模板发布后不建议直接修改，应生成新版本或在生成逻辑中增加特定规则。
