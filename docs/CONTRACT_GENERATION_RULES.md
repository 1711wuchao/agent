# 合同生成业务规则

## 数据来源

- 支持根据 Excel 表格中的销售方、购买方、开票日期、品名、规格型号、数量、税率、价税合计生成合同。
- 同一销售方、同一购买方、同一开票月份归并生成一份合同。
- 同一销售方、同一购买方但开票月份不同的，按月份分别生成合同。
- 合同日期按开票日期向前推算三个月确定。

## 合同类型判断

- 涉及“中城”的合同不得无条件走固定购销模板，必须先根据发票品名判断合同类型。
- 品名包含“站点”“软件”“算法”的，归为技术开发合同；涉及中城时同样适用该规则。
- 涉及“中城”但品名不属于技术开发范畴的硬件或产品类记录，使用中城固定购销模板。
- 其他硬件或产品类记录，归为产品购销合同。

## 进项/销项链条合同参照规则

- 上传文件名或批量生成需求中包含“进项”的，生成结果标记为进项合同。
- 上传文件名或批量生成需求中包含“销项”的，生成结果标记为销项合同。
- 进项/销项链条合同优先参照“五月份链条合同”正文结构生成购销合同，不再仅按文件命名处理。
- 进项链条合同正文采用短版购销结构：`买方/卖方`、标的与交货、知识产权及保密、结算付款、质量要求、双方责任、验收、终止、争议、其他。
- 销项链条合同正文采用长版购销结构：`甲方（需方）/乙方（供方）`、释义、合同项目、商品明细、价款、付款、包装运输、交货、保密、质量、售后、变更解除、通知、争议、反贿赂、其他。
- 进项/销项合同的 Word 文件命名参照样本格式：`进项合同_销售方_购买方_合同编号.docx` 或 `销项合同_销售方_购买方_合同编号.docx`。
- 正文甲乙方仍以合同法律关系为准：甲方为购买方，乙方为销售方。
- 进项/销项链条合同作为批量链条合同模式时，优先使用上述购销正文结构；未标记进项/销项的合同继续按普通合同类型规则判断。

## 编号与格式

- 合同编号不得出现汉字。
- 购销合同页数目标为 3-5 页。
- 技术开发合同页数目标为 10-15 页。
- 生成不同版本格式的合同，避免任意两份合同格式超过 70% 雷同。
- 自动优化合同排版。
- 表格跨页时，后续页需要保留表头。

## 条款要求

- 合同付款分 2 期。
- 合同签订后支付合同总金额 70%。
- 项目验收通过后 90-100 天内结清合同总金额未付款项。
- 硬件产品类合同需补充国家验收标准等内容。
- 软件产品类合同需明确技术目标、技术实现路径、验收节点、验收标准。

## 禁止内容

- 合同内不得出现“参考”。
- 合同内不得出现“参考文献”及相关信息。
- 品名内不得出现“通用设备”。
- 合同内容不得出现“不含税金额”“税额”。
- 合同中无需体现企业地址、法人信息。
- 无需设置法人签字页。
- 盖章页不得包含表格。

## 必须体现

- 合同内容必须体现税率。
- 合同内容必须体现价税合计。
- 合同内容必须体现数量。
- 合同内容必须体现规格型号。
- 送货地址仅标注“甲方工厂内指定地点”。
